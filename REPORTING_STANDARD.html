Agent Trend Reporting Standard

에이전트 트렌드 자료를 브리핑, 임원 공유, 플랫폼 전략 논의, 제품/기술 로드맵 조정에 바로 사용할 수 있도록 맞추는 운영 기준.

핵심 원칙

최신성조사 시점, 발표일, 제품 출시일, 스펙 버전, 인수/제휴/투자 시점을 구분한다. "최신"이라고 쓸 때는 확인 날짜를 남긴다.
출처 신뢰도공식 스펙, 표준 단체, 논문, GitHub 릴리스, 회사 공식 문서를 우선한다. 소셜 신호는 검증 전까지 미확인 신호로 분리한다.
브리핑 구조Executive Summary, What Changed, Technical Detail, AI Platform Implications, Recommended Actions, Risks, Inline Evidence를 기본 골격으로 쓴다.
기술 깊이아키텍처, API 계약, 데이터/상태 모델, 인증/인가, tracing/eval, failure mode, SDK 현황, 운영 난이도를 확인한다.

출처 우선순위

Source Catalog Source Watchlist Research Log A2A MCP UCP AP2 AG-UI A2UI
  1. 공식 스펙, 공식 문서, 표준 단체, 논문, GitHub 릴리스
  2. 회사 공식 블로그, 개발자 블로그, 제품 릴리스 노트
  3. 주요 언론과 분석기관
  4. 커뮤니티, 소셜, 개인 블로그

중요한 사실, 수치, 스펙, 커뮤니티 반응, 논문 주장은 하단 출처 섹션에 몰아두지 않는다. 해당 문단이나 섹션 바로 아래에 작은 source-pills 링크를 붙여 근거를 바로 확인할 수 있게 한다. 개별 보고서에는 독립적인 마지막 출처 모음을 두지 않고, 전체 링크 카탈로그는 인덱스와 watchlist에서만 관리한다.

AI 플랫폼 관점 필수 질문

  • 대화형 AI 서비스, 쇼핑/커머스, 로컬/지도, 결제, 콘텐츠, 사내 업무 중 어디에 직접 적용 가능한가
  • 중앙 AI 플랫폼 팀이 제공해야 할 공통 기능은 무엇인가
  • 서비스 팀이 직접 구현해야 할 도메인 기능은 무엇인가
  • 외부 표준을 그대로 채택할 것인가, 내부 호환 표준으로 감쌀 것인가
  • 개인정보, 결제, 메시징, 예약 같은 고위험 액션의 승인 흐름은 어떻게 둘 것인가
  • 경쟁사 대비 AI 플랫폼이 빠르게 차별화할 수 있는 데이터/서비스 접점은 무엇인가

금지 사항

출처 없는 단정확인되지 않은 사실을 확정적으로 쓰지 않는다.
홍보성 요약벤더 발표를 그대로 옮기지 않고 구현 가능성과 한계를 따진다.
일반 뉴스 나열AI 플랫폼/서비스 적용 포인트 없는 뉴스는 브리핑 우선순위에서 낮춘다.
변경점 누락기존 조사와 달라진 내용을 별도로 표시한다.
