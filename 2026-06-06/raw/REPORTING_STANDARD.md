# Agent Trend Reporting Standard

## 목적

이 자료는 단순 리서치 로그가 아니라 카카오 AI 서비스와 에이전트 플랫폼 의사결정을 돕는 브리핑 자료다. 브리핑, 임원 공유, 플랫폼 전략 논의, 제품/기술 로드맵 조정에 바로 사용할 수 있어야 한다.

## 원칙

### 1. 최신성

- 매 조사 시점과 기준 시간을 명시한다.
- 발표일, 제품 출시일, 스펙 버전, 인수/제휴/투자 시점을 구분한다.
- "최신", "최근", "현재"라고 쓸 때는 반드시 확인한 날짜를 함께 남긴다.
- 이전 문서와 달라진 점이 있으면 변경 전후를 분리해 쓴다.

### 2. 출처 신뢰도

출처 우선순위:

1. 공식 스펙, 공식 문서, 표준 단체, 논문, GitHub 릴리스
2. 회사 공식 블로그, 개발자 블로그, 제품 릴리스 노트
3. 주요 언론과 분석기관
4. 커뮤니티, 소셜, 개인 블로그

커뮤니티나 소셜에서 시작한 정보는 반드시 공식 출처 또는 독립 출처로 교차 확인한다. 확인되지 않은 내용은 "미확인 신호"로 분리한다.

중요한 사실, 수치, 스펙, 커뮤니티 반응, 논문 주장은 하단 Sources에만 몰아두지 않는다. 해당 문단이나 섹션 바로 아래에 작은 source pill 링크를 붙여 근거를 바로 확인할 수 있게 한다. raw 원본에는 같은 위치에 `참고 링크:`를 남긴다.

### 3. 브리핑 구조

모든 정기 브리프와 딥다이브는 가능한 한 아래 구조를 따른다.

- Executive Summary: 브리핑 독자가 5분 안에 읽을 핵심 판단
- Why It Matters: 시장, 기술, 경쟁, 카카오 관점의 의미
- What Changed: 새로 나온 사실 또는 기존 조사 대비 변경점
- Technical Detail: 아키텍처, 프로토콜, SDK, 보안, 운영 이슈
- Kakao Implications: 카카오 AI 서비스와 에이전트 플랫폼 적용 가능성
- Recommended Actions: 지금 할 일, 30일 내 할 일, 추적할 일
- Risks / Watch Items: 기술, 보안, 사업, 규제 리스크
- Sources: 확인한 링크와 신뢰도

### 4. 기술 깊이

기술 주제는 다음 항목을 가능한 한 확인한다.

- 아키텍처 구성요소
- 프로토콜 또는 API 계약
- 데이터 모델과 상태 모델
- 인증, 인가, identity, audit
- observability, eval, tracing
- failure mode와 fallback
- SDK/레퍼런스 구현 현황
- 운영 난이도와 migration cost
- 카카오 기존 서비스와 연결되는 integration point

### 5. 트렌드 판단

트렌드는 "새롭다"보다 "왜 지금 중요한가"가 핵심이다. 다음 기준으로 판단한다.

- 주요 플랫폼 벤더가 채택했는가
- 표준화 또는 오픈 생태계로 확산 중인가
- 실제 프로덕션 사례가 있는가
- 개발자 생태계와 SDK가 붙고 있는가
- 보안/거버넌스 논의가 성숙하고 있는가
- 카카오 서비스 자산과 결합했을 때 차별화 여지가 있는가

### 6. 카카오 관점 필수 질문

- 카카오톡, Kanana, 쇼핑/선물하기, 로컬/지도, 결제, 콘텐츠, 사내 업무 중 어디에 직접 적용 가능한가
- 중앙 AI 플랫폼 팀이 제공해야 할 공통 기능은 무엇인가
- 서비스 팀이 직접 구현해야 할 도메인 기능은 무엇인가
- 외부 표준을 그대로 채택할 것인가, 내부 호환 표준으로 감쌀 것인가
- 개인정보, 결제, 메시징, 예약 같은 고위험 액션의 승인 흐름은 어떻게 둘 것인가
- 경쟁사 대비 카카오가 빠르게 차별화할 수 있는 데이터/서비스 접점은 무엇인가

### 7. 금지 사항

- 출처 없는 단정
- 벤더 발표를 그대로 옮긴 홍보성 요약
- 기술 상세 없는 "중요하다" 수준의 평가
- 카카오 적용 포인트 없는 일반 AI 뉴스 나열
- 불확실한 내용을 사실처럼 표현
- 이전 조사와의 변경점 누락
