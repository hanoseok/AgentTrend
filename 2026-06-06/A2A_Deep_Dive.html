0. 브리핑 핵심 판단

Google A2A 발표 Linux Foundation 이관 A2A v1.0
결론. A2A는 에이전트 시대의 "서비스 간 협업 프로토콜" 후보다. 카카오는 A2A를 당장 전면 채택하기보다 내부 Agent Registry, Task 상태 모델, Artifact schema, 인증/인가, audit trace를 A2A-compatible하게 설계하는 것이 전략적으로 안전하다.
1. 플랫폼 계약내부 에이전트 플랫폼의 기본 계약을 A2A-compatible하게 잡을 것인가.
2. Agent Registry카카오 서비스별 Agent Card와 Agent Registry를 중앙 플랫폼 기능으로 제공할 것인가.
3. 고위험 액션 통제human approval, per-skill authorization, delegated token을 공통 표준으로 둘 것인가.
4. MCP 결합MCP와 A2A를 결합한 구조를 내부 AI 플랫폼 SDK에 포함할 것인가.

1. 왜 중요한가

시장 신호Google 발표 이후 Linux Foundation 프로젝트로 이동했고, 주요 기업과 클라우드 플랫폼 지원이 확대되는 흐름이다.
기술 신호MCP가 agent-to-tool 표준 후보라면, A2A는 agent-to-agent 표준 후보로 자리 잡는 중이다.
카카오 신호카카오톡, Kanana, 쇼핑/선물하기, 로컬/지도, 결제, 일정, 고객센터가 각각 독립 에이전트화될 경우 표준 위임 체계가 필요하다.
리스크 신호에이전트 간 위임은 개인정보, 결제, 예약, 메시지 발송 같은 고위험 액션을 확장하므로 보안/인가/감사 체계가 먼저 필요하다.

2. 현재 상태와 타임라인

A2A v1.0

판단: A2A는 아직 모든 산업의 사실상 표준이라고 보기에는 이르지만, MCP와 함께 에이전트 플랫폼의 표준 인터페이스 후보로 반드시 추적해야 한다.

4. 핵심 구성요소

Key Concepts Agent Discovery Specification
Agent Card에이전트의 이름, 설명, 엔드포인트, 지원 기능, 입출력 형식, 인증 요구사항, 스킬 정보를 담는 discovery 명세. 카카오 Agent Registry의 기본 단위 후보.
A2A Client / ServerClient는 작업을 위임하는 쪽, Server 또는 Remote Agent는 작업을 수행하는 쪽. 내부 구현과 모델 종류는 강제하지 않는다.
Message / Part에이전트 사이에서 오가는 요청과 응답의 구성 단위. 텍스트, 파일, 구조화 데이터 조각을 포함할 수 있다.
Task / ArtifactTask는 작업 상태를 관리하고 Artifact는 최종 결과물이다. 카카오에서는 UI와 액션으로 연결되는 구조화 결과물로 설계해야 한다.

Task lifecycle

상태의미카카오 UX/플랫폼 처리

5. 프로토콜 흐름

1. DiscoverAgent Registry 또는 공개 URL에서 Agent Card 탐색
2. Verify기능, 인증 요구사항, 입출력 형식 확인
3. Selectpolicy, ranking, eval 결과로 remote agent 선택
4. Sendmessage:send 또는 streaming 방식으로 작업 전달
5. TrackTask 생성, 상태 갱신, 진행 상황 수신
6. Approve필요 시 input_required 또는 auth_required 처리
7. ReturnArtifact 수신 후 사용자 경험으로 합성
  • discovery와 execution은 분리해야 한다.
  • 에이전트 선택을 모델 프롬프트에만 맡기지 말고 policy/ranking/eval 결과를 함께 써야 한다.
  • Task와 Artifact에는 traceId, contextId, userId/tenantId, approval state가 붙어야 한다.
  • 실패, 취소, 사용자 추가 입력 요청을 정상 경로로 설계해야 한다.

6. 보안과 거버넌스

Enterprise Ready Signed Agent Card

A2A는 인증과 인가를 프로토콜 자체의 마법으로 해결하지 않는다. HTTP, TLS, OAuth, OIDC, mTLS, API key 등 기존 엔터프라이즈 보안 메커니즘과 결합하는 방식에 가깝다. 따라서 플랫폼 구현자가 책임져야 할 영역이 크다.

Agent Card 위조/오염
잘못된 Agent Card 또는 악성 Agent Card가 registry에 등록될 수 있다.
Prompt injection 전파
한 에이전트가 받은 악성 지시가 위임 체인을 타고 다른 에이전트로 확산될 수 있다.
Delegated action 초과
사용자 권한을 초과한 결제, 예약, 메시지 발송이 발생할 수 있다.
추적 불가
장애나 오작동 시 어느 에이전트가 어떤 판단을 했는지 설명하기 어려울 수 있다.

필수 통제

Agent Registry 승인등록, 변경, 폐기, 버전 관리를 중앙에서 통제한다.
Signed Agent Card발급자 검증과 card tampering 방지를 포함한다.
Per-skill authorization에이전트 단위가 아니라 skill/action 단위로 권한을 제한한다.
Trace replaydelegation chain, prompt, tool call, approval state를 재현 가능하게 남긴다.

7. 카카오 AI 서비스 적용 방향

내부 Agent Registry카카오의 각 서비스 또는 도메인 에이전트를 Agent Card 기반으로 등록한다. 검색, 발견, 권한, SLA, 데이터 접근 범위, 정책 태그를 하나의 registry에서 관리한다.
Orchestrator와 전문 에이전트 분리사용자-facing 에이전트는 orchestration에 집중하고, 전문 에이전트는 자신의 도메인 기능, 정책, 데이터 접근, 액션 실행을 책임진다.
구조화 Artifact 중심 UX예약 후보, 선물 추천, 결제 요청, 일정 변경을 텍스트가 아니라 UI와 액션으로 연결되는 구조화 결과물로 다룬다.
Human-in-the-loop결제, 예약 확정, 메시지 발송, 개인정보 공유처럼 사용자에게 영향이 큰 액션은 명시적 승인을 받는다.
