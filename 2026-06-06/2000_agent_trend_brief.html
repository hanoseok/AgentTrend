6. Technical Detail

Workflow runtime MCP Docs UCP AP2 AG-UI
Workflow runtimeDynamic Workflows의 본질은 agent가 orchestration code를 만들고 병렬 실행/검증/재개를 운영하는 runtime이다. 카카오는 cost cap, model routing, trace, approval을 같이 설계해야 한다.
MCP enterprise shiftMCP RC는 stateless HTTP, MCP Apps, Tasks, auth/OIDC, deprecation policy를 강조한다. 카카오 MCP registry도 versioning과 task lifecycle을 포함해야 한다.
Skills evalGitHub는 skill install/publish 생태계를 밀고 있지만, SWE-Skills-Bench는 대부분의 skills가 효과가 제한적이라고 말한다. 배포 전 task eval이 필수다.
Commerce/UI stackUCP는 checkout/order, AP2는 mandate/audit, AG-UI는 streaming/interrupt/shared state를 다룬다. 카카오 서비스형 에이전트는 이 세 계층을 모두 봐야 한다.

7. Kakao Implications

  • 카카오 AI 플랫폼: Agent Registry와 MCP Registry를 통합하되 risk annotation, permission, Tasks, UI rendering, deprecation을 같이 관리해야 한다.
  • Kanana/카카오톡: AG-UI류의 streaming, interrupt, approval, shared state, user steering이 필요하다.
  • 쇼핑/선물하기/페이/로컬 예약: UCP/AP2 스타일의 checkout mandate, payment mandate, identity linking, order lifecycle을 검토해야 한다.
  • 사내 개발 플랫폼: agent task board, review queue, trace view, budget guardrail이 필요하다.

9. Risks / Watch Items

  • multi-agent workflows는 token 사용량이 급증할 수 있다.
  • MCP 서버와 sandbox agent는 host/resource 접근권한을 명시적으로 통제해야 한다.
  • skills는 task에 맞지 않으면 효과가 없거나 오히려 성능을 떨어뜨릴 수 있다.
  • commerce agent는 결제 승인, 책임, 분쟁 처리, audit trail이 가장 어렵다.
