1. Executive Summary

Copilot session streaming Google Agent Platform Microsoft Agent Confidence Stanford Future of Work Claude Science Fable 5 redeploy
핵심 판단 1: agent platform은 control plane이 된다

Google Agent Platform과 GitHub session/cost/model controls는 runtime, identity, gateway, registry, evaluation, observability, spend를 같은 운영 표면에 올리고 있다.

핵심 판단 2: 도입 우선순위는 task-level trust로 정한다

Microsoft confidence data와 Stanford worker agency data는 agent 도입을 직무 단위가 아니라 task confidence, worker-desired agency, reversibility, blast radius로 평가해야 함을 보여준다.

핵심 판단 3: release governance와 domain audit가 제품 요건이다

Anthropic Fable 5/Mythos 5 복구와 Claude Science는 model release gate와 domain artifact audit 없이는 위임 신뢰를 만들기 어렵다는 신호다.

이번 회차 결론: AI 플랫폼은 agent_session_ledger, ai_spend_policy, agent_identity_registry, agent_gateway_policy, human_agency_policy, domain_workbench_audit, model_release_gate를 "신뢰 가능한 위임 운영체계"로 통합해야 한다.

3. Project / Product / Policy Alerts

GitHub session streaming, credit pools, auto model selection

Copilot session streamingAI credit poolsAuto model selection

확인된 사실: GitHub는 Enterprise Cloud managed users 대상으로 Copilot agent session activity의 prompts, responses, tool calls를 streaming endpoint 또는 REST API로 볼 수 있게 했다. Cost centers는 monthly included AI credit pool cap을 지원하고, Copilot CLI auto model selection은 model health/utilization과 task dimensions를 고려해 모델을 고른다.

해석: agent 운영의 기본 단위가 seat나 request가 아니라 session, cost center, model route, tool call timeline으로 이동하고 있다.

적용 포인트: agent_session_ledger와 ai_spend_policy를 같은 trace id로 묶고, auto routing decision과 cost attribution을 함께 기록한다.

Google Gemini Enterprise Agent Platform

AnnouncementProduct page

확인된 사실: Google Cloud는 Gemini Enterprise Agent Platform을 build, scale, govern, optimize를 포괄하는 platform으로 발표했다. 구성 요소로 Agent Runtime, Memory Bank, Agent Identity, Agent Registry, Agent Gateway, Agent Simulation, Agent Evaluation, Agent Observability, Agent Optimizer, Model Armor 등을 제시한다.

해석: agent platform은 SDK나 workflow engine 하나가 아니라 identity, runtime, memory, gateway, eval, security dashboard까지 포함하는 control plane으로 포장되고 있다.

적용 포인트: agent_identity_registry, agent_gateway_policy, agent_registry_schema, agent_eval_runner, agent_observability_sink를 배포 단위로 묶는다.

Microsoft and Stanford task-level adoption confidence

Microsoft Agent ConfidenceStanford Future of Work

확인된 사실: Microsoft는 300명 technical experts와 101 tasks 기준의 Agent Confidence Index를 공개했고 평균 confidence를 64/100으로 제시했다. 조사에서 human-in-loop는 top priority였고 observability/monitoring/tracing도 주요 우선순위였다. Stanford SALT Lab은 1,500 workers, 104 occupations, 844 tasks 기반으로 automation desire와 worker-preferred agency를 분석했다.

해석: agent 도입의 좋은 단위는 "직무"가 아니라 "task + desired agency + confidence + reversibility + risk"다.

적용 포인트: delegation_trust_matrix를 만들어 task_confidence, human_agency_level, reversibility, blast_radius, evidence_required, approval_required, worker_preference를 기록한다.

Anthropic Fable 5/Mythos 5 redeploy and release governance

Anthropic redeployAxios contextWhite House EO

확인된 사실: Anthropic은 Fable 5/Mythos 5 접근을 복구했고, Amazon, Microsoft, Google, Glasswing partners와 shared jailbreak severity framework를 마련했다고 설명했다. Axios는 정부·업계 간 후속 검토와 불확실성을 보도했다. White House EO는 advanced AI의 national security considerations와 cyber defense modernization을 강조했다.

해석: frontier model release governance는 vendor-only safety note를 넘어 government-facing review, export control, severity framework, rollback, customer credits, model access communication까지 포함한다.

적용 포인트: model_release_gate에 pre-release adversarial eval, jailbreak severity taxonomy, customer exposure map, rollback trigger, export policy, government coordination log를 둔다.

Anthropic Claude Science and domain workbench expansion

Claude ScienceThe Verge context

확인된 사실: Anthropic은 Claude Science를 scientific AI workbench로 소개하며 auditable artifacts, curated skills/connectors, specialist agents, reviewer agent, HPC/SSH/Modal compute, sensitive data control을 강조했다. The Verge는 drug development ambition과 함께 실험·임상·규제 검증의 필요성을 보도했다.

해석: domain workbench는 agent의 유력한 제품화 단위다. 다만 life science 같은 영역에서는 "분석 자동화"와 "규제 가능한 결과" 사이의 간극을 명시해야 한다.

적용 포인트: domain_workbench_audit에 code/environment/message history, artifact lineage, citation/calculation check, reviewer verdict, human signoff, data boundary, external validation status를 넣는다.
