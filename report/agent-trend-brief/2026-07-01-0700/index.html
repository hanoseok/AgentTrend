3. Project / Product / Policy Alerts

Anthropic Claude Science and Sonnet 5

Claude ScienceClaude Sonnet 5AI for Science Briefing

확인된 사실: Anthropic은 Claude Science를 과학자를 위한 AI workbench로 공개했고, Sonnet 5를 coding, agents, professional work scale의 새 모델로 발표했다.

해석: vertical agent는 chat wrapper가 아니라 domain toolchain, compute access, auditable artifact, workspace governance를 묶는 제품이다.

적용 포인트: domain workbench template, artifact lineage, tool/package registry, compute quota, experiment audit, sensitive-domain access tier가 필요하다.

OpenAI GeneBench-Pro

GeneBench-ProCase studiesPaper

확인된 사실: OpenAI는 computational biology에서 ambiguity와 consequential judgment를 측정하는 GeneBench-Pro를 발표했다.

해석: agent eval이 단일 답변/코딩 task에서 multi-stage scientific reasoning, estimator choice, diagnostics, downstream go/no-go decision으로 이동한다.

적용 포인트: domain-specific eval packs, expert rubric, trace replay, intermediate decision grading, uncertainty/provenance scoring이 필요하다.

Google ADK Go 2.0 and Agent Quality Flywheel

ADK Go 2.0Agent Quality Flywheel

확인된 사실: Google은 ADK Go 2.0에서 graph-based workflow engine, built-in HITL, dynamic orchestration, unified node runtime을 공개했고, coding agent가 평가 데이터를 준비하고 inference, grading, failure analysis, optimization loop를 돌리는 Quality Flywheel을 소개했다.

해석: agent framework의 핵심은 graph composition과 evaluation automation을 결합하는 것이다.

적용 포인트: graph runtime, checkpoint/resume, human approval node, trace export, AutoRater integration, regression gate를 core runtime schema로 설계해야 한다.

LangChain Deep Agents guardrails, Harbor eval, Wiki Memory

Untrusted agent codeHarbor eval stackWiki MemoryDynamic Subagents

확인된 사실: LangChain은 Deep Agents에서 agent-written code의 execution isolation, capability isolation, durable pauses를 강조했고, Harbor/Deep Agents/LangSmith 기반 long-running agent eval stack과 wiki memory 패턴을 제시했다.

해석: agent runtime은 code execution, long-running eval, memory curation을 동시에 갖춰야 한다.

적용 포인트: sandbox 또는 capability-secure interpreter, resumable pause, long-running eval runner, memory ingestion/compaction/review workflow를 product primitive로 넣어야 한다.

Microsoft SkillOpt and reusable agent skills

SkillOpt

확인된 사실: Microsoft Research는 SkillOpt를 통해 agent skill files를 transfer 가능한 task-solving procedure로 최적화하는 방향을 제시했다.

해석: skills는 사람이 한 번 쓰는 운영 문서가 아니라 benchmark/eval과 연결해 지속 개선하는 외부 state가 된다.
